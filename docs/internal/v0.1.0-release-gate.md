## Clean-Machine Matrix

Both supported operating systems must record:

- operating-system version and artifact filename
- install or portable launch mode and checksum
- application launch and writable workspace
- profile creation, restart, and reload
- visible and background browser sessions
- Local HTTP instrumented example
- invalid browser URL and invalid executable behavior
- report creation and reopening after restart
- active-session shutdown and owned-process cleanup
- Windows unsigned-warning behavior and desktop-input limitation

## Real Hexcraft Matrix

The permitted Hexcraft target must record:

- target URL or build identifier without secrets
- one successful visible browser smoke session
- one successful background browser smoke session
- one guided directive using an action actually reported by the game
- one configured startup/UI flow, or a written blocker when no such flow is part of the supplied profile
- real successful action and state-change evidence
- real screenshot paths and accurate action/issue logs
- clean stop with no owned Chromium process
- report reopening after an application restart

Hexcraft-like unit fixtures do not satisfy this gate.

### Local Hexcraft Result

On 2026-08-03, the clean local Hexcraft checkout at commit `ed74dc25c0f00270ac4f9a8d092ef1db19abb6cf` was started from `/mnt/1tb/vscode/game` with:

```bash
npm run dev -- --host 127.0.0.1 --port 5173
```

Both background and visible final-AppImage runs completed the `Create New World` -> `Start World` startup flow, ran the forced valid `pause` directive, observed `pause-menu`, saved real PNG screenshots and structured action logs, reopened reports after restart, and left no owned browser or test process. Hexcraft reported that WebGPU was unavailable on this host and correctly used its existing WebGL 2 fallback; this did not prevent the test from passing.
